사내 데이터 셀프서비스 (Text2SQL)

문제. 비개발 부서의 수치 확인이 데이터팀 요청과 대기에 의존했습니다. 레거시 시스템은 서비스별로 같은 의미를 다른 컬럼명으로 써서, 자연어 질의를 데이터에 연결할 수 없는 상태였습니다.

  • 레거시 정제와 데이터 마트. 흩어진 운영 데이터를 단일 기준으로 표준화하고 조회 전용 마트로 재구성. 업무 용어와 실제 컬럼을 잇는 메타데이터 매핑으로 자연어 질의를 데이터에 정합.
  • 권한 우선 설계. 사용자별 접근 권한을 먼저 세우고, 권한을 통과한 읽기 전용 질의만 조회하도록 제한.
  • 시연 기반 확산. 각 팀의 반복 수작업을 현장에서 자동화해 보이는 시연으로 도입 저항을 해소.

플랫폼 통합 검색 (문서 RAG)

문제. 플랫폼 기본 검색이 필터 문자열 일치라 누락이 많고, 첨부 문서는 본문이 검색되지 않았습니다. 근거를 제시하지 못하는 답변은 신뢰를 얻지 못해, 근거 확인성을 검색 정확도와 동급 제약으로 두었습니다.

  • 입력 라우팅과 인덱스 설계. 스캔 PDF처럼 추출 텍스트가 없는 문서를 형식과 품질로 분기. 파일명과 게시 영역을 덧붙인 인덱스 텍스트로 dense 검색을 구성하고 HyDE, Self-query로 질의를 확장.
  • 리랭킹과 근거 통제. 1차 검색 풀에서 cross-encoder로 리랭킹하고, 근거 충분성을 자체 점검해 부족하면 조건을 완화해 재시도, 끝내 없으면 확인 불가로 중단하는 루프.
  • 랭킹 축 확장. 어휘 채널(FTS5)을 조건부 폴백으로 붙이고, 문서 역할 7종을 규칙으로 판정. 의미, 어휘, 필드 세 채널을 가중 RRF로 융합하되 어떤 채널도 끄지 않아 질의 오분류가 검색 붕괴로 이어지지 않게 구성.
  • 안정 재정렬과 결정론화. 점수 가산을 금지하고 역할이 맞는 문서만 제한적으로 끌어올림. 질의 이해와 관련도 게이트 온도를 0으로 고정해 평가 재현성을 확보. 전자결재 검색은 문서별 권한과 테넌트 격리를 검색 전 단계에서 강제.

배운 점

근거 확인성을 검색 정확도와 동급 제약으로 못박고, 하드 라우팅과 점수 가산을 배제한 채 신호로 채널 가중만 조절해 라우터 오분류가 검색 붕괴로 번지지 않게 했습니다. GPU가 없는 인프라 제약이 로컬 리랭커 대신 API와 어휘 방식을 쓰는 설계 선택을 실제로 결정했습니다.
