업무 자동화 오케스트레이션 에이전트와 재사용 실행 계층

역할 AI Engineer 담당 문제 재정의, 설계, 구현, 배포, 고객사 조율 기간 2025.03 ~ 재직중
OpenAI SDKTool CallingReAct자체 실행 루프2단 모델 라우팅FastAPIQdrantRedis

문제

제품의 설정 등록이 복잡해 미완료 상태로 문의가 반복되고, 도입 중도 포기가 발생했습니다. 설정 항목 개수와 탐색 경로가 병목이라, 인터페이스 자체를 대화형으로 대체하는 과제로 재정의했습니다.

다만 운영 데이터를 직접 바꾸는 작업이라, 권한과 검증과 승인을 원하는 위치에 둘 수 있어야 한다는 통제 요구가 있었습니다.

접근

  • 자체 실행 루프. 도구 실행 앞뒤에 통제를 삽입하기 위해 범용 프레임워크 의존을 제거하고, 의도 분석, 실행 계획, 도구 호출, 결과 검증, 응답 생성 루프를 직접 구현.
  • 재사용 실행 계층. 도구 화이트리스트, 입력 검증, 승인 분리, 접근 통제를 공통 미들웨어로 통합. 신규 기능이 선언 등록만으로 동일한 통제를 상속하도록 설계.
  • 2단 모델 라우팅. 도구가 늘수록 나빠지는 분류 품질과 비용을 2단 라우팅으로 분리. 후보 모델을 동일 조건으로 실측 비교해 구간별 계층을 나눔.

결과

71 → 97%
최상위 검색 적중률 (질의 31개 변형 채점)
약 50%↓
온보딩 설정 문의, 도입 이탈 해소
약 12배↓
라우터 분류 호출 단가 ($1.465 → $0.118 / 1,000회)

사용법 질의 31개 변형을 채점해 도구와 기능 라우팅의 최상위 적중률을 71%에서 97%로 올렸습니다. 온보딩 설정 문의는 약 50% 줄었고, 라우터 분류 호출 단가는 정확도가 동률인 조건에서 약 12배 절감했습니다.

배운 점

범용 프레임워크를 걷어내고 통제를 실행 루프에 직접 심어, 신규 도구가 선언만으로 동일한 안전장치를 상속하게 만든 재사용 설계가 핵심이었습니다. 관측 지표로 조용한 실패를 포착해 도구 선언 구조까지 교정했습니다. (12배는 시스템 전체가 아니라 라우터 분류 호출 단가 기준입니다.)
